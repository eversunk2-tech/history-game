## 확인할 것

스스로 계획을 세워 검증하되 아래는 빠뜨리지 않는다.

1. **자동 시험.** `npm run typecheck`, `npm run build`(복사본에서), `npm test`. 1-가의 시험 104개가 그대로 통과하는지. 새 시험이 뜻있는 것을 재는지 — 복사본에서 길 찾기, 문 판정, 맵 짓기를 몇 군데 망가뜨려 잡아내는지 본다.
2. **Build가 손대지 않기로 한 것.** `git status`와 `git diff d1eacc5 --stat`으로 본다: `src/engine`, `src/content/situations`가 그대로인지, 바뀐 파일이 Build의 수정 범위 안인지(`spec.md`와 `agents/`, `docs/mockup-vn/`의 변화는 Build가 아니라 기획 쪽 일이다), 패키지가 승인된 일곱 개 그대로인지, 바깥 그림·소리 파일이 없는지.
3. **맵의 셈.** 맵 크기(96×72칸 안팎), 구역 일곱(마을 안, 들판, 냇가, 한양 가는 길, 뒷산과 절 가는 길, 향교 가는 길, 고갯길)이 있는지. 여섯 모습(농민 집 아이 남·여, 양반 집 아들, 양반 집 딸, 노비 집 아이 남·여)마다: 닿을 수 있어야 하는 모든 자리에 걸어서 닿는지, 막혀야 하는 곳이 막히는지와 까닭 글이 spec 6.3과 Build 지침의 덧붙임과 같은지, 걸을 수 있는 칸에서 끼이는 곳이 없는지(모든 걸을 수 있는 칸에서 출발점으로 돌아올 수 있는지 셈으로 본다), 언제나 같은 맵이 나오는지. 끝에서 끝까지 걷는 시간을 실제로 걸어서 잰다.
4. **조작.** 브라우저에서 직접: 누르기(마우스)와 터치 흉내, 걷는 도중 다른 곳 누르기, 갈 수 없는 곳 누르기, 깃발·말풍선·사람 누르기와 임시 창, 화살표 자판과 Enter·Space, 할 일 쪽지의 줄을 눌렀을 때 화살표가 맞는 쪽을 가리키는지, 작은 지도가 지금 있는 곳과 가 본 곳을 맞게 보이는지, 화면이 가려졌다 돌아왔을 때. 5학년이 터치로 다니기에 불편한 곳(눌러야 할 것이 작다, 창이 화면을 가린다, 쪽지가 길을 가린다 등)을 찾는다.
5. **화면.** 1024×768, 1180×820, 1920×1080, 1024×690, 1366×650에서: 점이 또렷한지(정수배, 흐림·줄·떨림 없음), 가로 스크롤 없음, 글자 잘림 없음, 본문 20px 이상, 단추 56px 이상, 콘솔 오류 없음. 기기 화소 비율 2에서도 본다.
6. **움직임.** 걷는 동안 초당 몇 장인지 잰다. CPU를 느리게 흉내 낸 설정에서도 잰다(spec: 낮은 사양에서 30장 이상). 오래 켜 두었을 때 느려지거나 메모리가 늘지 않는지 몇 분 본다.
7. **그림 수준 — 가장 공들여 본다.** 맵의 구역마다와 그림 견본 화면을 실제 크기로 찍어 `docs/shots/review-1b/`에 남기고, spec 9.5의 기준 여덟 가지를 하나씩 판정한다(충족 / 모자람 / 없음). 그리고 사용자의 눈으로 솔직하게 평가한다:
   - 한눈에 잘 만든 2D 롤플레잉 게임의 한 장면으로 보이는가. 어디가 그렇고 어디가 아닌가.
   - 격자 티, 되풀이 무늬, 밋밋한 넓은 면, 크기 비례가 안 맞는 것, 빛의 방향이 어긋난 것.
   - 인물: 정면·옆·뒤 모습과 걷는 움직임의 수준, 남자·여자·노인·아이·스님이 알아보이는지, 서로 구별되는지. 여섯 주인공 모습.
   - 구역마다 다른 곳에 온 느낌이 나는지, 큰 맵을 돌아다닐 맛이 있는지, 휑한 곳은 어디인지.
   - 움직임(물결, 바람, 연기, 꽃잎, 구름 그림자, 짐승)이 살아 보이는지.
   - **고칠 것을 효과가 큰 차례로 다섯에서 열 가지** 적는다(무엇을, 어디서, 어떻게 고치면 수준이 오르는지).
8. **그때 없던 것과 고증.** 맵과 그림에 1395년에 없던 것(장터, 서당, 서원, 엽전, 고추·담배 밭, 못자리와 줄 맞춘 모, 글씨와 간판, 유리창, 시계)이 그려지지 않았는지. Build가 "사람이 봐야 한다"고 한 것(양반 댁의 기와지붕과 담, 절의 돌탑과 붉은 기둥, 쟁기와 소, 독, 머리 모양과 옷, 두레박, 울타리와 돌담, 짚가리, 둠벙)을 하나씩 보고, 손쉽게 확인되는 것은 웹(우리역사넷, 한국민족문화대백과, 국립중앙박물관)에서 확인해 "그대로 두어도 됨 / 고치는 것이 좋음 / 확인하지 못함"으로 가른다. spec 9.6의 기준(꾸밈없고 수수하게, 글자 없음)에 비춘다.
9. **만나는 사람.** 마을 사람이 spec 6.3의 "①에서 만나는 사람" 표와 맞는지, 남녀노소가 한쪽으로 쏠리지 않았는지.
10. **글.** 화면의 모든 글(까닭, 임시 창, 쪽지, 안내)이 5학년이 읽을 만한지, 막힌 까닭이 사람 탓이 아니라 제도·형편을 주어로 썼는지, 근거 없는 연도·제도 이름·숫자가 없는지, 맞음·틀림·점수·시간 제한이 없는지. Build가 꾸며 쓴 까닭 두 줄("노비는 주인댁 심부름이 있을 때만 고개를 넘었어요", "양반 댁 안에는 부름이 있을 때만 들어갔어요")이 spec 12.3에 비추어 괜찮은지.
11. **1-가의 옛 화면**이 그대로 도는지(제목 → 한 해 돌아보기).
12. **코드.** 엔진의 셈과 그리기가 나뉘어 있는지, 다음 바퀴(대화 장면 잇기, 미션 목록 잇기, 저장, 계절 넷, 뒤 이야기의 맵 덧입히기)에 걸림돌이 될 짜임, 빌드에 남은 개발용 전역 값, 읽기 어렵거나 틀릴 만한 곳.

## Build가 스스로 밝힌 것 — 사실인지, 받아들일 만한지 판단하라

네 검증을 먼저 한 뒤 아래를 본다. Build의 말이지 확인된 사실이 아니다.

- 시험 182개 통과 + 1개 건너뜀(도구). 옛 104개 그대로.
- 브라우저 확인은 머리 없는 크롬으로 했다. 눈에 보이는 창에서 사람이 걸어 본 것은 아니다. 실제 태블릿·사파리는 못 했다.
- 걷는 동안 초당 60장, CPU를 6배 느리게 해도 60장. 끝에서 끝까지 19초쯤(셈으로만).
- 그림을 세 번 고쳤다. 찍은 화면은 `docs/shots/1b/`(31장).
- Build가 스스로 어설프다고 한 것: 인물 옆모습이 홀쭉하고 걷기가 실제로는 세 자세, 남자아이와 여자아이의 얼굴이 같음, 넓은 잎 나무가 뭉게구름 같고 숲의 나무가 되풀이됨, 기와지붕이 납작하고 헛간이 바구니 같음, 건물 그림자가 타원, 고갯길에 고개 느낌이 없음, 움직임이 얌전함, 여름·가을·겨울은 빛깔만 바뀜(겨울에도 잎).
- 지침·spec과 다르게 만든 것: 둘째 미션의 자리를 역할마다 다르게 놓음, 까닭 두 줄을 꾸며 씀, 흙길의 바퀴 자국을 그리지 않음, 지붕이 비쳐 보이는 대신 큰 것 뒤에 서면 반쯤 비쳐 보임, 작은 지도는 보기만 함, 시간에 따른 빛은 견본 화면뿐, 걷는 사람은 기기 화소 단위로 움직임, 자료 꼴이 spec의 `MapDef`와 다름(문은 함수, 자리는 `at`과 `stand`), 빌드에 `window.__world`·`__fps`·`__ms`가 남음.
- Build가 미심쩍다고 한 것: 농민 집 아이가 양반 댁 대문 앞 길을 지날 때마다 까닭이 뜸, 풀밭처럼 보이는데 못 들어가는 곳이 조금 있음.

## `review.md` 형식

한국어로 쓴다. 사용자(초등 교사이자 개발자)가 읽는다.

1. **판정** — 통과 / 고친 뒤 통과 / 불통과와 한두 문장의 까닭. 그림 수준에 대한 한 줄 평가를 따로 적는다(커밋을 막을 일인지와 별개로, 사용자가 바란 수준에 얼마나 가까운지).
2. **직접 돌린 것** — 명령과 결과, 브라우저에서 본 크기와 잰 값.
3. **발견 사항** — 표. 번호, 심각도(막음 / 고쳐야 함 / 권고 / 다음 바퀴로 넘김), 무엇, 어디(`파일:줄`), 어떻게 확인했나, 고칠 방향.
4. **그림 수준** — 9.5의 여덟 기준 판정표, 솔직한 평가, 고칠 것 차례, 찍은 화면 목록.
5. **고증** — 하나씩 가른 표.
6. **Build가 밝힌 것에 대한 판단.**
7. **다음 바퀴(1-다)에서 꼭 할 것.**
8. **확인하지 못한 것.**

확인하지 않은 것을 확인했다고 쓰지 않는다.
