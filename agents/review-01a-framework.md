# Review 서브에이전트 지침 — 바퀴 1-가 (게임의 틀)

## 맡은 일

Build 서브에이전트가 만든 「조선에서 한 해 살기」 바퀴 1-가(게임의 틀)를 **직접 돌려서 검증**하고, 결과를 프로젝트 루트의 `review.md`에 쓴다.
너는 Build와 다른 에이전트다. Build가 무엇을 했다고 말했는지가 아니라, 지금 폴더에 있는 것이 실제로 어떻게 움직이는지를 근거로 판정한다.

먼저 `CLAUDE.md`, `spec.md` 전체, `agents/build-01a-framework.md`(Build가 받은 지침)를 읽는다. 판정 기준은 spec 11절의 "Review 통과 기준"과 Build 지침의 "이번에 만드는 것"이다. 이번 범위는 11절 표의 "1-가" 줄뿐이다(견주어 보기, 생각 나눔, 수첩, 선생님 자료, 대본, 제대로 된 그림, 농민 집 말고 다른 집의 장면은 범위 밖이다).

## 확인할 것

스스로 계획을 세워 검증하되, 아래는 빠뜨리지 않는다.

1. **자동 시험.** `npm run typecheck`, `npm run build`, `npm test`를 직접 돌려 결과를 적는다. 시험이 통과하는 것만 보지 말고 **시험이 뜻있는 것을 재는지** 본다. 복사본에서 규칙을 두세 군데 일부러 망가뜨려(수치 범위 묶기, 잠김 판정, 씨앗 난수, 8장면 등) 시험이 잡아내는지 확인한다.
2. **규칙(spec 5절).** 한 판이 정확히 8장면인지, 계절마다 내 장면 1 + 세상 장면 1인지, 수치 0~10, 선택 하나의 변화 -3~+3, 잠긴 선택지와 까닭, 결과 갈림, 같은 씨앗 같은 판, 날씨 비율(가뭄 3 · 보통 5 · 풍년 2), 수치가 0이어도 끝나지 않는지, 장면마다 고를 수 있는 것이 하나 이상인지. 엔진(`src/engine`)이 화면·브라우저·시간·`Math.random`을 쓰지 않는 순수 함수인지.
3. **콘텐츠 검사기.** spec 11절에 적힌 검사 항목이 실제로 들어 있고, 잘못된 자료를 넣으면 잡아내는지(복사본에서).
4. **자료만 더하면 풀리는지.** 복사본에서 다른 집(예: 양반 집 아들)의 장면 파일을 실제로 더해, 코드 수정 없이 그 집을 뽑거나 고를 수 있는지 본다. 상황 폴더를 하나 더했을 때 "준비 중"이 풀리는지도 본다.
5. **화면.** 브라우저에서 1024×768, 1180×820, 1920×1080 세 크기로 제목부터 한 해 돌아보기까지 한 판씩 끝까지 한다. 가로 스크롤 없음, 글자 잘림·겹침 없음, 본문 20px 이상, 선택지 단추 높이 56px 이상, 잠긴 선택지에 자물쇠와 까닭이 보이는지, 수치 변화가 색만이 아니라 글자·화살표로도 보이는지, 콘솔 오류가 없는지. 서로 다른 날씨(가뭄·보통·풍년)와 잠긴 선택지가 나오는 판을 골라서 본다. 다시 하기와 저장(localStorage `joseon-year/v1`)도 본다. 화면이 바뀐 직후 잠깐 누름을 받지 않게 만들었다고 하니, 자동으로 누를 때는 사이를 띄운다.
6. **퀴즈가 아님.** 맞음·틀림 표시, 점수, 등수, 시간 제한이 화면과 코드 어디에도 없는지.
7. **글.** 견본 8장면과 화면의 모든 글이 글자 수 예산(지문 100자, 선택지 26자, 결과 90자, 배움 쪽지 50자)과 말투(지문·결과는 "나"의 이야기체, 쪽지는 "~했어요")를 지키는지, 초등 5학년이 읽을 만한지, 7절의 수위 원칙에 어긋나는 말이 없는지. 이야기가 앞뒤로 어긋나는 곳(예: 풍년이 뽑혔는데 흉작을 말하는 지문)이 있는지.
8. **고증.** 견본 8장면의 지문·결과·쪽지에 나오는 사실(연도, 제도 이름, 숫자, 생활 방식)을 장면의 근거 번호 → `src/content/sources.ts` → spec 12.2 순서로 대조한다. 근거 목록에 없는 사실, spec 12.3에 "확인하지 못했다"고 적힌 것을 사실처럼 쓴 곳을 모두 찾는다. `sources.ts`의 글이 spec 12.2와 같은지도 본다. 출처 쪽 원문 대조는 1-나에서 대본을 쓸 때 하기로 되어 있으니, 이번에는 "근거 목록 안에서만 썼는가"와 "1-나에서 반드시 대조할 것"을 가려 적으면 된다. 손쉽게 확인되는 것은 웹(우리역사넷, 한국민족문화대백과)에서 확인해도 좋다.
9. **저작물.** 외부 그림 파일이 없는지, 그림이 모두 코드로 그려졌는지. 지도서 문장을 옮겨 쓴 곳이 없는지 — 지도서를 풀어 둔 텍스트가 `…/scratchpad/guide-u2.txt`에 있다(임시 파일). 견본 장면의 문장을 몇 개 골라 그 안에서 찾아본다.
10. **약속 지키기.** `package.json`에 사용자가 승인한 일곱 패키지(`vite`, `typescript`, `preact`, `@preact/preset-vite`, `@preact/signals`, `vitest`, `pretendard`)만 있는지. Build가 수정 범위 밖을 건드리지 않았는지(`git status`로 생긴 파일을 본다. 커밋이 없어서 모두 새 파일로 보인다).
11. **코드.** 읽기 어려운 곳, 쓰이지 않는 코드, 틀릴 만한 곳, 다음 바퀴(네 집 채우기, 상황 더하기, 전쟁 뽑기, 견주어 보기)에서 걸림돌이 될 짜임.

## Build가 스스로 밝힌 것 — 사실인지, 받아들일 만한지 판단하라

네 검증을 먼저 한 뒤 아래를 본다. 이것은 Build의 말이지 확인된 사실이 아니다.

- spec 10절의 자료 꼴에 칸을 더했다: `Condition.max`, `Condition.notFlags`, `Scene.textVariants`, `Scene.sample`, `RoleDef.wishOutcomes`, `Situation.endings`.
- "한 해 이름"이 여섯 가지다(spec은 다섯 가지쯤).
- 고르기 화면의 상황 한 줄 소개를 spec 6.1 표보다 짧게 줄였다(44자 안).
- 검사기에 spec에 없는 글자 수 예산을 더했다(잠긴 까닭 30자 등).
- 날씨를 여름 계절 열기에서도 보여 준다.
- 봄 농민 장면 "책대로"의 "가뭄이면 살림 -2"는 여름 농민 장면의 갈린 결과에서 깎인다.
- 결과 갈림은 바탕 결과를 통째로 갈음한다. 엔진은 ±3을 넘는 변화를 던지지 않고 ±3으로 묶는다.
- `statusLocks`는 엔진이 아니라 검사기가 본다.
- 작은 이름표(계절 띠, 수치 이름, "준비 중", 상자 머리글)는 1024×768에서 18px이다. 본문·선택지·까닭·쪽지는 20px이다.
- HUD에 "처음으로" 단추와 확인 창, 화면이 바뀐 뒤 0.3초 누름 막기, 주소의 `?seed=숫자`를 넣었다.
- 예시 네 장면(봄 세상, 봄 농민, 가을 세상, 겨울 세상)의 결과 글은 spec 표에 없어 Build가 꾸며 썼다.
- Build가 미심쩍다고 한 것: 견본 장면의 "마을에 온 소금 장수"(1395년에 그랬는지 근거 없음), 쪽지의 "한 해 가운데 밤이 가장 긴 날"(근거 목록에 없는 말), 봄 세상 결과의 "집에 돌아오니"(일꾼이 얼마나 머물렀는지 확인되지 않음, 가을에야 돌아온다는 지문과 어긋날 수 있음), 풍년이 뽑혀도 "벼가 성기다" "농사를 망친 건넛집"이 나옴, HUD의 "날씨 풍년"이라는 말, 인심이 깎이는 선택이 없어 인심이 쌓이기만 함.
- Build가 하지 못했다고 한 것: 실제 태블릿·터치 확인, 한 판 시간 재기, 빌드본으로 완주.

## `review.md` 형식

한국어로 쓴다. 사용자(초등 교사이자 개발자)가 읽는다.

1. **판정** — 통과 / 고친 뒤 통과 / 불통과 가운데 하나와 한두 문장의 까닭.
2. **직접 돌린 것** — 명령과 실제 결과(시험 수 포함), 브라우저에서 본 크기와 판.
3. **발견 사항** — 표. 번호, 심각도(막음 = 커밋 전에 꼭 고쳐야 함 / 고쳐야 함 = 이번 바퀴에 고치는 것이 좋음 / 권고 / 1-나로 넘김), 무엇이 문제인지, 어디(`파일:줄`), 어떻게 확인했는지(다시 해 볼 수 있게), 고칠 방향.
4. **Build가 밝힌 것에 대한 판단** — 항목마다 받아들임 / 고쳐야 함 / spec을 고쳐야 함.
5. **1-나에서 꼭 할 것** — 대본을 쓸 때 대조해야 할 고증 목록 등.
6. **확인하지 못한 것** — 하지 못한 검증과 까닭.

발견한 것이 없으면 없다고 쓴다. 확인하지 않은 것을 확인했다고 쓰지 않는다.
