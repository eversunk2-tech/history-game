## 확인할 것

1. `npm run typecheck`, `npm run build`(복사본), `npm test`.
2. **꼭 고칠 것 1·2번**을 처음 확인한 방법 그대로: 계절 닫기가 풀린 미션만 "해낸 일"로 적는지(덤 미션은 "하는 중"), 꼭 할 일을 다 푼 뒤의 안내가 띠가 한 줄인 화면(1280×800, 1366×650, 1920×1080)에서도 보이는지.
3. **새로 들어간 것 — 봄을 다시 끝까지 해 본다**(두 모습, 미션만 하는 길과 덤까지 하는 길, 덤의 네 선택지를 모두).
   - 덤의 한마디가 쪽지와 말풍선에 뜨는지, 가 보고 싶게 만드는지, 글의 한도 안인지.
   - 덤의 선택 둘(우물가, 뒷산): 어느 쪽도 정답처럼 보이지 않는지, 변화가 없는 결과에서 화면이 어색하지 않은지("살림·기력·인심은 그대로예요"), 해 ☀를 쓰고 얻는 것이 없다고 느껴지지 않는지. 새 역사 사실이 지어 넣어지지 않았는지(대본과 근거).
   - 볍씨: 뿌린 곳과 빈 곳이 눈으로 갈리는지, 다 뿌린 뒤 무엇을 누를지 알 수 있는지, 점수처럼 보이는 것이 없는지, 줄 맞춰 심는 모양이 아닌지, 어떻게 해도 이야기가 이어지는지.
   - 처음 맵에 들어섰을 때의 안내가 차례로 뜨는지, 해 ☀ 풀이가 알맞은 때에 뜨는지. 알림이 너무 많거나 길어 읽기도 전에 사라지지 않는지.
   - 대화 장면: 띠가 한 줄로 줄어 승인된 시안(`docs/mockup-vn/`)의 느낌에 가까워졌는지, 선택지가 뜰 때 사람이 비켜서는 것이 자연스러운지와 얼굴이 가려지지 않는지(사람 하나·둘, 선택지 둘·셋, 잠긴 까닭 줄이 있을 때 — 1024×690 포함), 4:3에서 몸이 잘리는 것이 거슬리는지.
   - "미션이 풀림" 종이에서 같은 말이 되풀이되지 않는지, 고친 글(12·13번)이 자연스러운지, 남은 어려운 말이 있는지.
   - **재미와 짜임이 처음과 견주어 어떻게 달라졌는지** 솔직하게 적는다. 아직 약한 곳과, 손이 적게 들면서 효과가 클 다음 손질을 적는다.
   - 시간을 처음과 같은 방법으로 다시 잰다(미션만 / 덤 셋까지).
4. **저장.** 꼴이 3으로 올랐다고 한다. 꼴 2의 저장(견본과 네가 지난번에 만든 것)이 옮겨져 읽히는지, 결과 대화나 종이가 떠 있을 때 끄고 이어 하면 종이가 뜨고 닫은 뒤에는 다시 뜨지 않는지, 망가진 저장 세 가지(5번)에서 화면이 멈추지 않는지, 처음 확인한 26가지 때의 새로 고침이 그대로 맞는지(지난번에 하나가 기대와 달랐다 — 그것도). 저장 견본 시험.
5. **그 밖의 번호**: 6·7·9·14·15·19·20번을 하나씩.
6. **고치다가 망가진 것이 없는지.** 처음 통과했던 것을 다시 본다: 막다른 길 0(엔진으로 모든 길 — 덤에 선택이 생겼다), 무작위 판, 화면 크기 열두 설정에서 끝까지와 넘침, 자판만으로, 손가락 흉내만으로, 그림 13장과 그림이 없을 때, 인터넷 끊김, 맵(문과 까닭, 끼이는 칸, 초당 장수), 빌드본에 개발용 값이 없는지, 손대지 않기로 한 폴더와 패키지.
7. **Build가 바꾼 버릇이 괜찮은지**: 쪽지가 접힌 채 시작하는 것, 꼭 할 일을 다 했다는 말이 세 곳(띠·알림·쪽지)에 뜨는 것, 넓은 화면에서 띠가 높아지는 것, 줄인 띠를 어둡게 한 것, 우물가에서 듣기만 하면 인심이 오르지 않게 된 것, 봇짐 맨 위의 수치 풀이, 걷다가 문 한 칸 안에 멈추면 지나가는 길이어도 까닭이 뜨는 것.
