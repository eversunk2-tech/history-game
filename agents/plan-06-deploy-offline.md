# Plan 서브에이전트 지침 6 — 배포(Vercel)와 인터넷 없이 열리기

`spec.md`에 사용자 결정을 반영한다. 수정 범위는 `spec.md` 하나다. 구현, 설치, git 작업을 하지 않는다.

## 사용자가 한 말 (2026-10-08)

"vercel에서 history game으로 깃허브에서 import해 와서 프로젝트 생성했어. 인터넷 없이도 열리게 해줘."

## 내가 확인한 것

- GitHub 저장소 `eversunk2-tech/history-game`의 `main`에 Vercel이 이어졌다. 커밋 `b428159`(1-가와 기획서까지)의 운영(Production) 배포가 성공했다(GitHub의 배포 기록으로 확인). 앞으로 `main`에 푸시할 때마다 새 판이 올라간다. `CLAUDE.md`의 Embed 단계가 "커밋하고 GitHub에 푸시한다"로 바뀌었으므로, 바퀴가 Review를 통과할 때마다 운영 주소의 게임이 바뀐다.
- 배포마다 생기는 주소(`history-game-…-psc23.vercel.app`)와 팀 이름이 붙은 주소(`history-game-psc23.vercel.app`, `history-game-git-main-psc23.vercel.app`)는 열면 Vercel 로그인 화면으로 넘어간다(배포 보호). 학생은 열 수 없다.
- `history-game.vercel.app`은 **다른 사람의 사이트**다(제목이 "APUSH Game"). 우리 것이 아니다.
- 그러므로 학생에게 줄 **공개 운영 주소가 무엇인지는 아직 모른다.** Vercel 화면의 Domains에서 사용자가 확인하거나 새로 정해야 한다. 내가 사용자에게 묻고 있다.
- 프로젝트에 `vercel.json`은 없다. 빌드 명령은 `vite build`, 결과 폴더는 `dist`, `base`는 `./`다.

## 정해진 것 (13.1에 확정으로 적는다)

1. **배포는 Vercel**, GitHub `main`에 푸시하면 저절로 올라간다. 13.2의 "배포할 곳과 주소"에서 "곳"은 풀렸고 "주소"만 남았다(사용자에게 묻는 중).
2. **인터넷 없이도 열리게 한다**(서비스 워커). 13.2의 8번에서 "넣을지"는 풀렸다.

## 기획에 반영할 것

1. **언제 넣는가.** 앞서 권장안은 "①을 다 만든 1-마에서"였다(새 판이 나올 때 옛 판이 남는 걸림 때문에). 사용자가 넣으라고 했으므로, **옛 판이 남지 않게 하는 방식으로 태블릿 바퀴(1-다 바로 뒤)에 넣는 것**을 기본으로 다시 짠다. 더 늦추어야 할 뚜렷한 까닭이 있으면 그 까닭과 함께 권장안을 내되, 그 경우에도 사용자가 물은 것에 "언제부터 인터넷 없이 열리는지"를 한 문장으로 답할 수 있게 적는다.
2. **새 판과 옛 판.** 바퀴마다 운영 주소에 새 판이 올라간다. 정할 것:
   - 인터넷이 될 때는 늘 새 판을 받아 오고, 안 될 때만 담아 둔 판으로 여는 방식(예: 첫 문서는 인터넷 먼저, 이름에 해시가 붙은 파일은 담아 둔 것 먼저)과 그 밖의 방식을 견주어 권장안을 낸다.
   - 게임을 하는 도중에 새 판이 내려왔을 때: 하던 판은 끝까지 가고 다음에 열 때 바뀌는지, 알림을 띄우는지. 초등 5학년이 수업 중에 헷갈리지 않아야 한다.
   - 담아 둔 옛 파일을 지우는 때, 판 번호를 화면 어디에 보이는지(선생님 자료의 "이 기기" 줄).
   - 처음 연 날 무엇까지 담아 두는지(그림 파일이 많아지면 수십 MB가 된다 — 9.4의 용량 한도와 맞춘다. 한꺼번에 담을지, 연 이야기부터 담을지).
   - 새 패키지 없이 손으로 쓰는 길을 기본으로 하고, 플러그인을 쓰는 길은 견준 길로만 적는다.
3. **저장과 새 판.** 학생이 이야기 도중일 때 새 판이 올라가면 저장의 꼴이 달라질 수 있다. 저장에 판 번호를 두고 옛 저장을 새 꼴로 옮기는 규칙, 옮길 수 없을 때의 처리(깬 기록은 지킨다)를 5.4와 10절에 다시 분명히 적는다. **학생이 쓰기 시작한 뒤에는 저장을 깨뜨리는 변화를 올리지 않는다**는 원칙과, 수업에 쓰는 동안에는 푸시를 조심해야 한다는 것(또는 수업용 판을 따로 고정하는 길)을 적고, 필요하면 사용자 결정에 올린다.
4. **주소.** 공개 운영 주소가 정해지면 그 주소를 spec에 적을 자리를 만든다(지금은 "사용자 확인 중"). 주소가 정해지기 전에 만들 수 있는 것과 없는 것을 가른다. 배포 보호 때문에 미리 보기 주소로는 학생 기기에서 시험할 수 없다는 것을 적는다. 주소를 바꾸면 기록이 사라진다는 원칙은 그대로다.
5. **Vercel 설정.** `vercel.json`이 필요한지(서비스 워커와 첫 문서가 오래 담기지 않게 하는 머리말, 매니페스트의 종류 등) 믿을 만한 자료로 확인해 적는다. 확인하지 못한 것은 "배포한 뒤 확인"으로 적는다.
6. **11절**: 태블릿 바퀴의 범위와 Review 기준(인터넷을 끊고 아이콘으로 열기, 새 판을 올린 뒤 옛 판이 남지 않는지, 도중에 끊겨도 그 계절이 되는지)을 고치고, 사용자가 실제 기기에서 해 볼 점검표의 10번(와이파이와 새 판)을 이에 맞게 고친다. 1-나가 커밋되어 올라가면 맵만 먼저 태블릿에서 걸어 볼 수 있다는 것도 적는다(주소가 정해지면).

## 끝나면 보고할 것

- 인터넷 없이 열리게 하는 방식의 권장안과 넣는 바퀴, 사용자가 물으면 답할 한 문장("언제부터, 어떻게 하면 인터넷 없이 열리는가")
- 새 판이 올라갈 때 학생 화면에서 일어나는 일
- 저장과 새 판에 대한 원칙, 사용자가 정해야 할 것이 있으면 그것
- Vercel 설정에서 필요한 것과 확인하지 못한 것
