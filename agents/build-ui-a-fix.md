# Build 고침 지침 — 3판 다듬기 ㉠ 고침 바퀴

조정자가 쓴 지침이다. ㉠의 Review(`agents/review-ui-a.md`)가 **"고친 뒤 통과"**로 판정했다. 판정과 근거는 `review.md` 맨 끝의 "## 3판 다듬기 ㉠ — 한 바퀴의 겉" 절에 있다. 아래만 고친다. 처음 지침 `agents/build-ui-a.md`의 "지킬 것"·"고치지 않는 것"은 그대로다.

## 고칠 것

1. **맵 띠 한 줄 안내 19px → 20px** — `band.css`의 `.band-hint`가 1.1875rem이라 1024 너비(1024×768·1024×690)에서 19px이다. 문장은 20px부터(지금 판도 20px). 1.25rem으로 되돌리고, 1024에서 안내가 잘리지 않고 띠 높이가 지금 판(1024×768 122px) 아래로 남는지 잰다. `design.test.ts`에 이 자리(띠의 문장)가 1.25rem 아래로 가지 않는지 보는 시험을 더한다(지금 시험은 18px 바닥만 봐서 놓쳤다).
2. **대사 창 초점 테가 위 가장자리에서 안 보임** — 한지빛 3px 테가 말하는 사람의 흰 옷과 1.3~1.8:1이다(기준 3:1, 어느 바탕에서든). `talk.css`의 `.talk`(`--focus`)와 `button.talk-box:focus-visible`에서 **먹 테와 한지빛 테를 두 겹**으로 겹친다(예: 안쪽 한지빛 + 바깥 먹, 또는 `outline` + `box-shadow`). 그림 위·한지 위 어디서든 한 겹은 3:1을 넘는지 찍어서 잰다. 대화 장면 밖의 초점 테(먹)는 그대로.
3. **뽑힌 아이 종이에 잇달아 누르기 막음이 없음** — 움직임 줄이기 기기에서 종이가 0ms에 떠서, 패 아래를 0.12초 간격으로 두 번 누르면 둘째 누름이 "…로 한 해 살기 ▶"를 눌러 바로 소개로 넘어간다(보통 설정도 0.7초 뒤 둘째 누름). `RolePick.tsx`의 종이·`role-go` 단추에, 종이가 뜬 뒤 `src/ui/advance.ts`의 `OPEN_GAP_MS`(380ms) 동안 누름을 받지 않게 한다(옛 모습 고르기 화면의 400ms 막음과 같은 뜻 — 이미 있는 `TapGate`나 상수를 쓰고 새 틈 값을 만들지 않는다). 자판 Enter·Space도 같은 틈을 지킨다. `advance.ts`의 넘기기 동작은 바꾸지 않는다(가져다 쓰기만).
4. **미리 받기: 주아 + 제목 그림** — 조정자가 정했다(`spec.md` 4.3 끝의 "고침"). `vite.config.ts`의 `FIRST_SCREEN`에서 주아 줄을 살린다. 빌드본의 `index.html`에 미리 받기 줄 둘(그림·주아, 주아는 `crossorigin`)이 들어가는지, 주아의 미리 받은 파일이 CSS가 받는 것과 같은 것으로 쳐져 두 번 받지 않는지(망 기록에서 주아 요청 1번) 확인한다. 첫 글이 지금 `main` 빌드본보다 늦지 않은지 같은 조건(10Mbps·40ms·CPU 4배·캐시 없이, 5번 가운데값)으로 다시 잰다.
5. **권고 — 할 것**
   - 1366×650에서 제목 아래 소개 글이 산 그림 위에 놓여 글자 화소 5%가 3.5:1이다. 소개 글에 옅은 한지빛 빛 그림자(`text-shadow`)를 주어 4.5:1 넘게 한다(다른 크기에서 모양이 탁해지지 않게).
   - 1366×650에서 저장 알림 줄이 뜨면 알림 상자의 아래 점선이 "이어 하기" 단추에 7px 덮인다. 겹치지 않게 맞춘다.
   - 시험 보강: ① `drawHero`의 씨앗 갈래 이름 `'hero'`를 고정하는 시험(같은 씨앗의 기대 결과를 못 박거나 `subSeed(seed,'hero')`를 직접 견줌) ② Review의 망가뜨려 보기에서 못 잡은 화면 동작 셋을 지키는 시험 — 뒤집은 뒤 "← 이야기책"이 없음, 뽑힌 모습대로 `settleRole`에 넘김, 처음 판에는 "살아 보지 않은 집과 모습이 더 자주 나와요." 줄이 없음(소스 시험이든 렌더 시험이든 지금 시험 틀에 맞는 쪽으로). 시험을 넣은 뒤 그 동작을 일부러 망가뜨려 실제로 잡는지 본다.

## 고치지 않는 것
