# Review 서브에이전트 지침 — 바퀴 1-가 다시 보기

## 맡은 일

네가 `review.md`에 적은 발견 사항 가운데 Build가 고쳤다고 한 것을 **직접 돌려서 다시 확인**하고, `review.md`에 결과를 덧붙인다.

Build가 받은 지침은 `agents/build-01a-fix.md`다. 고치기로 한 번호는 1·2(꼭), 3·4·5·6·9·10·12(함께)이고, 7·8·11·13과 14~22는 손대지 않기로 했다.

## 수정 범위

- 앞과 같다. 고칠 수 있는 파일은 **`review.md` 하나뿐**이다. 코드를 고치지 않는다.
- 망가뜨려 보는 시험과 파일을 더해 보는 시험은 스크래치패드의 복사본에서 한다. 앞에서 쓴 `rv/` 폴더의 복사본은 옛 코드이니 새로 복사한다.
- 패키지 설치, git 커밋·푸시를 하지 않는다. 띄운 서버는 끝나면 멈춘다.

## 확인할 것

1. `npm run typecheck`, `npm run build`(복사본에서), `npm test` 결과.
2. **1번**: 1024×690과 1366×650에서 본문 20px 이상, 선택지 단추 56px 이상인지. 그 크기에서 글자 수 예산을 꽉 채운 장면과 결과가 넘치거나 잘리지 않는지. 1024×768, 1180×820, 1920×1080에서 앞의 측정값과 달라진 것이 없는지, 한 판이 끝까지 가는지.
3. **2번**: 복사본에 바람 줄 없는 집의 장면 파일을 더했을 때 그 집이 "준비 중"으로 남는지. 한 해 돌아보기가 실패하거나 엔진이 던질 때 빈 화면이 아니라 알리는 화면이 나오고 처음으로 돌아갈 수 있는지. 새로 더한 시험이 이 잘못을 실제로 잡는지(복사본에서 고친 것을 되돌려 본다).
4. **3·4·5·6·9·10·12번**: 고친 것이 맞는지, 새 검사기 알림 셋(읽히지 않는 표시, 근거 글에 없는 숫자, 갈린 결과가 빠뜨린 카드·표시)이 실제로 알리는지(복사본에서 그런 자료를 넣어 본다), 알림이 시험을 깨지 않는지.
5. **고치다가 망가진 것이 없는지.** 앞 검증에서 통과했던 것(모든 길 걷기, 날씨 비율, 잠긴 선택지, 저장, 다시 하기, 퀴즈 요소 없음, 승인된 패키지 일곱 개, 수정 범위)을 다시 본다. Build가 손대지 않기로 한 것(견본 장면의 글·수치, `spec.md` 등)이 그대로인지도 본다. 앞 검증 때의 파일 해시가 스크래치패드에 남아 있으면 견주어 무엇이 바뀌었는지 본다.
6. 새로 생긴 것(이어 갈 수 없을 때 나오는 화면, 위쪽 띠의 날씨 줄, 높이가 낮을 때의 여백 규칙)에 문제가 없는지.

## `review.md`에 덧붙일 것

맨 위 판정 아래에 "다시 본 날과 최종 판정"을 한 줄 더하고, 문서 끝에 **"7. 다시 보기"** 절을 만든다.

- 번호마다: 고쳐짐 / 덜 고쳐짐 / 고쳐지지 않음, 어떻게 확인했는지
- 새로 찾은 문제(있으면 앞과 같은 표 꼴로, 번호는 23번부터)
- 최종 판정: 통과(커밋해도 됨) / 다시 고쳐야 함

앞에 쓴 내용은 지우지 않는다. 고쳐진 항목은 3절 표에서 지우지 말고 7절에서 가리킨다.

## 끝나면 보고할 것

최종 판정, 번호별 결과 한 줄씩, 새로 찾은 문제, 확인하지 못한 것.
