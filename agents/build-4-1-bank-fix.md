# Build 지침 — 4-1 ㉮ 은행 고침 바퀴

조정자가 쓴 지침이다. ㉯(은행 검증)의 판정은 "고친 뒤 통과"다. 기준은 `docs/bank/review-4-1.md`의 6절(고칠 문제 6, 권고 6), 7절(근거 줄의 말 8), 8절(번호를 다시 적은 여덟), 9절(한양 지도)이다. 처음 지침 `agents/build-4-1-bank.md`의 규칙(글 한도, "~요", 근거, 지도서를 옮기지 않음, 겹침 검사, PDF 위치를 적지 않음)은 그대로다.

## 할 것

### 1. 고칠 문제 여섯(6절 표 — 모두 고친다)
- 2-1-0006 (실제로 있었던 일인 고를 것을 분명히 틀린 것으로), 2-1-0079 ("양인 남자면" 꼴, 풀이도), 2-2-0050 ("조선 전기"로 좁힘, 풀이도), 2-2-0009 (고를 것의 "그림 위" → 위쪽 여백, 풀이에서 해를 뺌), 2-2-0062 ("흔히"를 뺌), 2-1-0050 (꾸민 글에 〈예〉 같은 틀).
- 6절 표의 "고칠 방향"을 따르되, 더 나은 말이 있으면 써도 된다. 그때는 근거 안의 말인지 다시 열어 본다.

### 2. 권고 여섯(6절 "권고" 표 — 모두 고친다)
- 2-2-0053 (표 이름에 1413년), 2-2-0044 (노비의 일 — "허드렛일"을 빼고 집안일·농사 같은 일로), 2-1-0069 ("맨 먼저 꼽은" 꼴), 2-1-0012 (불교를 우스개로 읽힐 수 있는 고를 것을 불교와 무관한 틀린 것으로), 2-1-0053·0071 (안향의 때를 한쪽으로 맞춤), 2-2-0071·0070 ("장계향"이라는 이름 — 출처 쪽에 있으면 근거 줄 F119에 더하고, 없으면 괄호를 뺀다).

### 3. 근거 줄의 말 여덟(7절 — `bankSources`)
- F101·F103·F104·F107·F109·F114·F115·F120을 7절대로 고친다. 고친 줄은 출처 쪽을 다시 열어 확인하고, `docs/bank/sources.md`의 같은 줄도 맞춘다.

### 4. 번호를 다시 적은 여덟(8절 — 조정자가 정함)
- 저장소의 `src/content/sources.ts`에 이제 F05·F07·F16·F30·F33·F53·F68·F85 줄이 있다(㉢이 spec 12.2에서 옮겼다).
- **F53으로 되돌린다**: F121을 단 문제(2-2-0039·0058·0075)의 근거를 F53으로 바꾸고, `bankSources`에서 F121 줄을 없앤다. (조정자가 spec 12.2 F53의 출처 칸에 hm_133_0010을 더했다.)
- **F68로 되돌린다**: 2-2-0078의 근거를 F122 → F68로 바꾸고, 풀이를 F68의 사실 칸이 받쳐 주는 만큼으로 줄인다(예: "주로 여자들이었어요" — 8절). `bankSources`에서 F122 줄을 없앤다.
- **나머지 여섯은 새 줄을 남기고, 원래 번호를 덧붙인다**: 8절 표의 "원래 사실 칸이 받쳐 주는 것"에 든 문제마다 원래 번호를 `facts`에 더한다(F05 — 2-2-0001·0002·0003·0006·0010·0011·0015·0016·0017, F07 — 2-2-0052·0058, F16 — 2-1-0076·0077, F30 — 2-2-0058, F33 — 2-2-0067, F85 — 2-1-0061·0062·0076). 2-2-0003의 "글 모르는 백성" 까닭은 F05(와 E9)가 받친다 — F107에 그 말이 없으면 0003의 근거에서 F107을 빼도 된다.
- `bankSources` 머리 주석의 바꾼 번호 목록(F05→F107 …)을 이 결정에 맞게 고친다. 번호가 비는 자리(F98·F99·F121·F122)는 그대로 비워 둔다(새 번호를 당겨 쓰지 않는다 — 한 번 쓴 번호를 다른 뜻으로 다시 쓰지 않는다).

### 5. 한양 지도(9절)
- `docs/bank/hanyang-map.md` 머리에 "틀이 가로세로 100의 정사각형이니, 화면에서는 가로세로를 같은 비율로 늘린다(찍는 둘레가 둥글게 남게)"를 더한다.

### 6. 판과 기록
- 글·답·고를 것·풀이·근거 가운데 하나라도 바뀐 문제는 `ver`를 2로 올린다(id는 그대로). 주제 파일의 `bankVer`를 고친 날로.
- `docs/bank/build-4-1.md` 끝에 "고침 바퀴" 절: 고친 문제마다 무엇을 어떻게 바꿨나(한 줄), 바꾼 근거 번호, 다시 연 쪽과 날짜.
- `docs/bank/review-4-1.md`·`sample-4-1.md`는 ㉯의 것이다. 고치지 않는다(㉯가 다시 본 뒤 표본을 맞춘다).

## 일하는 자리와 확인

- 같은 때 ㉢의 Build가 저장소의 작업 폴더를 고치고 있다. 처음 바퀴처럼 **복사본에서 일한다**: `e539062`를 스크래치 `bank-41/fix/`에 `git archive`로 풀고, 그 위에 저장소의 지금 `src/content/bank/`(두 JSON·`sources.ts`)·`docs/bank/`·**`src/content/sources.ts`**(㉢이 여덟 줄을 옮긴 것)를 복사한다. `node_modules`는 링크한다.
- 복사본에서 세 명령(`npm run typecheck`, `npm test`, `npm run build`) — 검사기 잘못 0·알림 0, `content4.test.ts`의 알림 시험 통과. 복사한 `sources.ts` 때문에 다른 시험이 깨지면 고치지 말고 보고한다.
- 고친 문제의 글에 대해 겹침 검사(지도서 PDF와 14자 이상 0)를 다시 한다.
- 끝나면 두 JSON·`src/content/bank/sources.ts`·`docs/bank/`의 `sources.md`·`build-4-1.md`·`hanyang-map.md`만 저장소에 옮긴다. 저장소의 다른 파일(특히 `src/content/sources.ts`)은 건드리지 않는다. 옮긴 뒤 저장소에서 `npm test -- tests/bank.test.ts`만 돌려 본다.
