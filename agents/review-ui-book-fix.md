# Review 다시 보기 지침 — 이야기책 조각 고침 바퀴

조정자가 쓴 지침이다. 처음 Review(`agents/review-ui-book.md`)의 규칙은 그대로다. Build가 `agents/build-ui-book-fix.md`대로 고쳤다. Build의 말은 견주기만 하고, 판단은 직접 돌려서 얻는다.

## 무엇을 보나

- 사용자의 저장소 폴더(가지 `ui-design`)의 커밋하지 않은 바뀜 가운데 이번 고침: `src/screens/RolePick.tsx`(패 누름의 틈), `tests/design.test.ts`(시험 다섯).

## Build가 밝힌 것

1. `RolePick.tsx` — 누가 될까가 처음 그려질 때 `const [cardGate] = useState(() => new TapGate(Date.now()))`, 패의 `onClick`은 `if (cardGate.pass(Date.now())) setPicked(index);`. 마우스·손가락·Enter·Space 모두 이 누름. 96가지(4크기 × 줄이기 끔·켬 × 마우스·손가락 × 표지·펼친 줄 × 0.09·0.15·0.2초)에서 저절로 뒤집힘 96 → 0, 틈 뒤 한 번 누르면 96/96 뒤집힘.
2. `design.test.ts` +5 — 패의 문, 꾸밈의 `aria-hidden`(번호 원·갈피끈·표지 그림), 갈피끈 `pointer-events: none`(어느 규칙도 다른 값을 주지 않음), 움직임 줄이기의 `transition: none`(`button.book-row`, `.btn`), 도장의 붉은 값(여러 꼴을 읽는 빛깔 읽개). 망가뜨려 보기 21/21. 시험 972 → 977.
3. 미심쩍은 것: 느린 기기에서 문이 화면이 보이기 전에 서면 0.38초보다 짧게 막을 수 있음, 처음 0.38초는 일부러 누른 패도 받지 않음.

## 볼 것

1. 세 명령(시험 수, 지운 시험 0, 빌드본에 `open2`·`devOpenShelf` 없음).
2. 처음 Review의 권고 1(두 번 누름)을 **처음과 같은 스크립트·크기·간격**으로 다시 잰다(새 판·바탕 `983ad3b`). 틈이 지난 뒤 한 번 누름이 늘 받히는지, 처음 들어올 때 패가 늦게 받히는 것이 아이에게 "안 눌린다"로 느껴질 만큼인지(0.38초).
3. 권고 2: 처음 못 잡은 빈틈(번호 원·갈피끈 `aria-hidden`, 갈피끈 `pointer-events`, 줄이기의 `transition: none`, 띄어 쓴 붉은 값)을 처음과 같은 방법으로 다시 망가뜨려 이제 잡는지. 새 빛깔 읽개가 뇌록·한지빛·그림자를 잘못 잡지 않는지.
4. 새로 생긴 탈: 누가 될까의 다른 동작(뽑힌 아이 종이의 380ms 막음, 되풀이 키 막음, 움직임 줄이기에서 패가 바로 뒤집힘, "← 이야기책")이 그대로인가, 이어 하기·저장으로 들어올 때도 같은가. 바뀐 파일이 위 둘뿐인가.
5. 한 바퀴(제목 → 처음부터 → 이야기책 → ① → 패 → 뽑힌 아이 → 소개)를 1024×768·1180×820·1366×650에서, 콘솔 오류 0.
6. 개인 정보 검사(조정자가 준 낱말 목록, 바뀐·새 파일).
