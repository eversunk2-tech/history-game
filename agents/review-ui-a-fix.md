# Review 다시 보기 지침 — 3판 다듬기 ㉠ 고침 바퀴

조정자가 쓴 지침이다. 처음 Review(`agents/review-ui-a.md`)의 규칙은 그대로다. Build가 `agents/build-ui-a-fix.md`대로 고쳤다. Build의 말은 견주기만 하고, 판단은 직접 돌려서 얻는다.

## 무엇을 보나

- 사용자의 저장소 폴더(가지 `ui-design`)의 커밋하지 않은 바뀜 가운데 이번 고침: `band.css`, `talk.css`, `screens.css`, `RolePick.tsx`, `vite.config.ts`, `fonts.css`(설명 줄), `tests/design.test.ts`, `tests/engine.test.ts`. 조정자가 `spec.md` 4.3 끝에 "고침"(미리 받기 = 주아 + 제목 그림)을 적었다.

## Build가 밝힌 것

1. `.band-hint` 1.25rem — 1024×768·1024×690에서 20px, 띠 113.4px 그대로. 1366×650은 한 줄 띠라 안내가 원래대로 숨는다.
2. `button.talk-box:focus-visible`만 — 먹 3px `outline`(3px 띄움) 둘레를 한지빛 `box-shadow` 9px가 감쌈. 위 가장자리 열마다 3:1 넘는 몫 100%, 가장 낮은 열 3.7:1.
3. `RolePick.tsx` — 종이를 띄울 때 `TapGate(Date.now())`(`ui/taps.ts`, 380ms), "…로 한 해 살기 ▶"는 `gate.pass`를 지나야 `settleRole`. Enter·Space도 단추 누름이라 같은 틈.
4. `FIRST_SCREEN`에 주아 줄을 살림 — 빌드본 미리 받기 2줄, 망 기록에서 주아 요청 1번. FCP 지금 판 1,036ms = 새 판 1,036ms, 글꼴 다 쓰임 2,611 → 1,638ms, 1,762KB.
5. `.title-lead`에 한지빛 `text-shadow` 세 겹(1366×650 글자 화소 5% 3.5 → 5.9:1), `screens.css`에 `@media (max-height: 700px)`로 제목 쪽 여백만 줄여 알림과 "이어 하기" 사이 −7 → +31px.
6. 시험 940 → 948(946 통과·2 건너뜀) — `design.test.ts` 18 → 25, `engine.test.ts` +1(`'hero'` 고정). 망가뜨려 보기 11가지 모두 잡음.

## 볼 것

1. 세 명령(시험 수, 지운 시험 0).
2. 처음 Review의 "고쳐야 함" 셋과 권고 셋이 실제로 풀렸는지 — 처음 찍은 자리와 같은 방법(같은 스크립트·같은 화면 크기)으로 다시 잰다. 초점 테는 **화소 단위**로 다시 잰다(처음의 66%가 3:1 아래였던 그 셈으로).
3. 패 잇달아 누르기: 움직임 줄이기 켬·끔, 마우스·손가락(`Input.dispatchTouchEvent`)·Enter·Space. 틈이 지난 뒤에는 한 번 누름으로 넘어가는지(막음이 너무 길거나 영영 막히지 않는지).
4. 미리 받기: 주아가 두 번 받히지 않는지, 제목이 처음부터 주아로 그려지는지(바뀌는 순간 그림), FCP가 지금 판보다 늦지 않은지(번갈아 5번 이상 가운데값).
5. 새로 생긴 탈: 낮은 화면 `@media`가 1024×690·1366×650 말고 다른 크기(1920×1080·1280×800·1180×820)의 제목을 바꾸지 않았는지, 빛 번짐이 하늘 위에서 탁해 보이지 않는지, 두 겹 초점 테가 대사 창 글·리본·꼬리를 가리지 않는지, 띠 안내 20px로 1024에서 다른 칩이 밀리지 않는지.
6. 새 시험이 약하지 않은지(망가뜨려 보기 몇 가지를 직접 — 스크래치 사본에서).
7. 한 바퀴를 여덟 설정에서 다시 돌려 글 잘림·가로 넘침·겹침 0, 콘솔 오류 0.
8. 개인 정보 검사(바뀐·새 파일).
