## 확인할 것

1. `npm run typecheck`, `npm run build`(복사본), `npm test`. 옛 104개가 그대로인지.
2. **꼭 고칠 것 1~5번**을 네가 처음 확인한 방법 그대로 다시 본다: 화살표가 쪽지·작은 지도에 가려지지 않는지(여덟 자리, 1024×768과 1920×1080), 길목 셋에서 길과 주인공이 보이는지, 여섯 모습으로 사람을 눌렀을 때의 이름, 까닭이 쪽지와 겹치지 않는지, 문장의 글자 크기와 1024×690에서 쪽지가 넘치지 않는지.
3. **그림 — 가장 공들여 본다.** 맵의 구역과 그림 견본 화면을 실제 크기로 다시 찍어 앞에 찍은 것(`docs/shots/review-1b/`)과 나란히 견준다. 9.5의 여덟 기준을 다시 판정하고, "배경 7할, 인물 5할"이라던 네 평가가 어떻게 달라졌는지 솔직하게 적는다.
   - 인물: 옆모습, 걷기 넉 장이 모두 다른 자세인지와 걷는 모습이 자연스러운지(잇달아 찍어 본다), 남녀·어른·노인이 얼굴 둘레에서 갈리는지, 같은 사람으로 보이던 어른 남자 셋, 일하는 몸짓, 누가 될까 화면.
   - **살빛**: 신분에 따라 살빛이 갈리지 않는지(여섯 주인공과 마을 사람의 정의를 읽고 화면에서 본다).
   - 넓은 잎 나무와 숲, 길목, 고갯길(고개로 읽히는지, 걸을 수 있는 칸과 문이 맞는지), 경계와 얼룩, 휑하던 둘레, 초가와 그림자, 소.
   - 1920×1080에서 느티나무가 한 화면에 드는지. 움직임이 얼마나 늘었는지(네가 잰 방법으로 다시 잰다). 거슬리게 번쩍이거나 어지럽지 않은지.
   - 새로 놓은 것(도랑과 널다리, 물새, 돌무더기, 쓰러진 나무, 늙은 소나무)에 그때 없던 것이나 눈에 거슬리는 것이 없는지.
4. **고치다가 망가진 것이 없는지.** 처음 검증에서 통과했던 것을 다시 본다: 여섯 모습 모두 끼이는 칸 0, 보이는 자리에 모두 닿음, 문 × 모습의 까닭이 spec·지침과 같음(고갯길의 문 자리가 옮겨졌다고 한다), 무작위 누르기에서 벽에 걸침 0, 다섯 화면 크기와 화소 비율에서 정수 배율과 또렷함(1920×1080의 배율이 5에서 4로 바뀌었다고 한다), 초당 장수, 메모리, 1-가의 옛 화면, 손대지 않기로 한 폴더, 패키지 일곱 개.
5. **Build가 바꾼 버릇이 괜찮은지**: 할 일 쪽지가 걷기 시작하면 접히는 것, 까닭이 화면 아래 가운데에 뜨는 것과 문 쪽으로 가려 할 때만 뜨는 것(맵 끝 길목도 같은 규칙이 되었다고 한다 — 길목에 다가갔을 때 까닭을 못 보고 지나치는 일은 없는지), 느티나무 가까이에서 화면이 나무 쪽으로 쏠리는 것(어지럽지 않은지), 끝에서 끝까지 걷는 시간이 고개를 넣어 24초쯤으로 늘어난 것.
6. **Build가 꾸며 붙인 이름**("주인댁 어른", "농민 집 젊은이", "누님", "오라버니", "양반 댁 아주머니" 등)이 5학년이 읽기에, 그리고 spec 7.3에 비추어 괜찮은지.
7. 빌드본에서 개발용 전역 값과 주소 매개변수가 정말 안 먹는지.
