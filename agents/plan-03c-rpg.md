# Plan 서브에이전트 지침 3-다 — 미연시식 대화 + 롤플레잉(맵 돌아다니기) + 게임다운 재미

`agents/plan-03-round1b.md`, `agents/plan-03b-visual-novel.md`에 덧붙이는 지침이다. **게임의 짜임이 크게 바뀐다.** 지금 고치고 있는 `spec.md`에 함께 반영하되, 이번 판은 사용자가 다시 읽고 승인해야 한다(승인 전에는 구현하지 않는다). 수정 범위는 그대로 `spec.md` 하나다.

## 사용자가 한 말 (2026-10-08)

"게임 대화 방식과 구조도 미연시 게임처럼 해줘. 그리고 롤플레잉 느낌 나게 해주며, 맵에서 돌아다니고 하는 장면은 코드로 그리는데 시중 2D 롤플레잉 게임과 비슷하게 높은 수준의 그래픽으로 작업해줘. 그리고 게임적 재미가 있는 요소가 더 있도록 구성해줘."

정리하면 네 가지다.

1. **대화 방식과 구조를 미연시처럼.** 화면 구도만이 아니라, 인물들이 이름표를 달고 말을 주고받고, 대화 안에서 선택지가 갈리는 흐름.
2. **롤플레잉 느낌.** 주인공이 맵에서 돌아다니며 사람을 만나고 일을 겪는다.
3. **맵 장면은 코드로 그린다.** 시중 2D 롤플레잉 게임에 견줄 만한 높은 수준의 그래픽으로.
4. **게임다운 재미 요소를 더한다.**

대화 장면의 배경·인물 그림은 앞서 정한 대로 캔바 그림 생성(시안 승인 뒤 확정)이다. 맵 장면은 코드로 그린다.

## 지켜야 할 것 (바뀌지 않는다)

- 사용자가 확정한 것: 일곱 상황, 연대순으로 하나씩 만들기, 역할 네 가지, 지도서 차시와의 연결, 서버·로그인 없음, 로컬 개발.
- 이 게임의 뿌리: **퀴즈가 아니다. 규칙과 놀이 자체가 학습 내용이다.** 맞음·틀림·점수·등수가 없다. 재미 요소를 더하더라도 "역사 내용과 상관없는 놀이를 붙인 것"이 되면 안 된다. 더하는 요소마다 "이것으로 무엇을 겪고 배우는가"를 한 줄로 댈 수 있어야 한다.
- 고증 원칙(12절), 수위 원칙(7절), 저작물 원칙(남의 게임·지도서·옛 그림을 베끼지 않는다).
- 수업에서 쓴다: 40분 수업, 교실 태블릿(터치)과 TV. 본문 20px 이상, 단추 56px 이상.
- 1-가에서 만든 것(규칙 엔진의 수치·잠김·결과 갈림·씨앗 난수·날씨 뽑기, 콘텐츠 검사기, 시험 104개)은 되도록 살린다. 버려야 하는 것은 무엇이고 왜인지 적는다.

## 기획할 것

### 1. 한 판의 짜임을 다시 정한다 (4절, 5절)

- **맵 → 대화 → 맵**의 흐름: 계절마다 느티골 맵을 돌아다니다가 사람이나 장소에 닿으면 미연시식 대화 장면으로 들어가고, 끝나면 맵으로 돌아온다.
- 지금의 "계절마다 세상 장면 1 + 내 장면 1"은 **꼭 겪는 큰일**로 남기는 것을 권한다(학습 내용과 분량의 뼈대). 그 밖에 맵에서 고를 수 있는 작은 일(마을 사람과 이야기, 일손 돕기, 구경, 물건 구하기)을 둔다.
- **한 계절에 할 수 있는 일에 한도를 둔다**(예: 기력이 곧 움직일 힘). 맵에 있는 일을 다 할 수 없어서 어디로 갈지가 곧 선택이 되게 한다. 다른 방법이 더 낫다고 보면 그것을 제안한다.
- **신분에 따른 잠김을 공간으로 옮긴다.** "여자는 향교에 다닐 수 없었어요"가 선택지의 자물쇠뿐 아니라 맵에서 들어갈 수 없는 곳, 말을 걸 수 없는 사람, 허락 없이 나갈 수 없는 길로 드러나게 한다. 까닭 한 줄은 그대로 보인다. ⑦에서는 이 잠김이 사라진다(전차는 삯만 내면 누구나 탄다).
- 미연시식 대화의 요소를 정한다: 말하는 사람 이름표, 인물 표정, 눌러서 넘기기, 대화 안의 선택지, 지난 대화 다시 보기. 저장하고 이어 하기가 필요한지도 정한다(한 판이 길어지면 필요하다).
- **한 판의 시간을 다시 셈한다.** 돌아다니기가 들어가면 길어진다. 한 판(한 해)을 몇 분으로 잡을지, 40분 수업에서 어떻게 쓸지(한 해를 한 차시에 끝내는지, 계절 단위로 끊어 이어 하는지) 안을 내고 사용자 결정에 올린다.

### 2. 게임다운 재미 요소 (5절에 새 항목)

후보를 넓게 낸 뒤, **넣을 것 / 나중에 넣을 것 / 넣지 않을 것**으로 가르고 까닭을 적는다. 넣을 것마다 "무엇을 겪고 배우는가"와 어느 상황에서 쓰는지를 적는다. 생각해 볼 것:

- 몸으로 하는 작은 놀이(미니게임): 볍씨 뿌리기·모내기·김매기·가을걷이, 길쌈, 장터에서 값 치르기(쌀과 베, 뒤 상황에서는 엽전), 피란 짐 싸기 등. 예를 들어 "논에 바로 뿌리면 여름 김매기가 네댓 번, 옮겨 심으면 두세 번"이 놀이의 횟수와 품으로 느껴지게 하면 규칙이 곧 내용이 된다.
- 할 일 목록(퀘스트), 가진 물건(쌀·베·소금·엽전 등)과 살림 수치의 관계.
- 모으는 것: 생활 카드, 수첩(도감), 한 해 이름(끝맺음)이 여러 가지인 것, 숨은 일(인심이 높아야 열리는 일 등).
- 마을 사람들과의 사이(인심을 마을 전체 하나로 둘지, 사람마다 둘지).
- 상황을 넘나드는 재미: 같은 느티골이 시대에 따라 달라진 것을 찾아보기(1395년에는 없던 장터가 1795년에 생김 등). 견주어 보기와 이어진다.
- 넣으면 안 되는 것도 적는다: 역사와 상관없는 싸움·레벨 올리기, 맞히면 점수를 주는 문제, 운에만 기대는 뽑기 보상, 시간에 쫓기게 하는 것.

### 3. 맵 (9절, 10절)

- **느티골 맵 하나를 일곱 상황이 함께 쓰되 시대에 따라 달라지게** 하는 것을 권한다(①에는 없던 것이 뒤 상황에 생긴다). ⑦은 한성 맵이 더 필요하다. 맵에 놓을 곳(집, 논밭, 마을 어귀 느티나무, 우물, 관아 가는 길, 향교, 절, 장터 등)을 상황 ①을 기준으로 정하고, 상황별로 달라지는 것을 표로 적는다. 놓는 것마다 근거가 있는지 본다(예: 1395년 마을에 장터를 그리지 않는다).
- 보는 방향과 움직임: 위에서 내려다보는 2D(시중 2D 롤플레잉의 보통 방식)를 기본으로 하고, 태블릿에서의 조작(가려는 곳을 누르면 걸어감 / 화면의 방향 단추)과 TV·PC에서의 조작(자판)을 정한다. 초등 5학년이 터치로 쉽게 다닐 수 있어야 한다.
- **그래픽 수준과 그리는 방법.** 맵은 코드로 그린다(바깥 그림 파일을 쓰지 않는다). "시중 2D 롤플레잉 게임에 견줄 만한 수준"을 무엇으로 볼지 기준을 적는다: 타일의 갈래와 변화(풀·흙길·논물·밭이랑), 건물(초가·기와집)과 나무의 입체감과 그림자, 네 방향으로 걷는 인물의 움직임, 물결·바람 같은 움직이는 타일, 계절에 따라 바뀌는 빛깔(봄·여름·가을·겨울)과 날씨(비·눈), 앞뒤 가림, 주인공을 따라가는 화면. 화풍(예: 16비트 시절의 도트 그림 느낌)을 하나로 정하고, 대화 장면의 캔바 그림과 한 게임 안에서 어울리게 할 방법을 적는다.
  - 코드로 그린 그림이 손으로 그린 상용 게임의 수준에 바로 닿기는 어렵다. 어떻게 수준을 끌어올릴지(그림을 화면에 찍어 보며 고치는 되풀이, 타일·인물을 한 장에 늘어놓은 견본 화면, Review가 그림을 보는 기준)를 11절에 적는다.
- 기술: 지금의 Vite + TypeScript + Preact 위에 캔버스로 직접 그리는 작은 맵 엔진을 두는 길과, 게임 틀(Phaser 등)을 새로 들이는 길을 견주어 권장안을 낸다. 새 패키지가 필요하면 사용자 결정에 올린다(지금 승인된 것은 일곱 개뿐이다). 규칙 엔진과 화면을 나누는 원칙은 지킨다. 자료의 꼴에 맵·사람·일의 자리·대화가 어떻게 더해지는지 10절에 적는다.

### 4. 분량과 만드는 순서 (8절, 11절)

- 맵·미니게임·대화가 더해지면 상황 하나의 분량이 크게 는다. 상황 하나에 드는 것(맵 변화, 사람 수, 큰일과 작은 일의 수, 미니게임, 대화 그림 수)을 다시 세고, 일곱 상황 전체가 감당할 만한지 본다. 줄일 곳을 제안한다(맵과 미니게임을 상황끼리 함께 쓰기 등).
- **사용자가 빨리 해 볼 수 있게 얇은 한 조각부터** 만드는 순서를 권한다: 예를 들어 ① 1395년의 봄 한 계절을 맵·대화·미니게임 하나까지 끝까지 만들어 해 보게 한 뒤, 의견을 받아 나머지 계절과 집을 채운다. 바퀴를 다시 나누고, 바퀴마다 사용자가 무엇을 해 볼 수 있는지 적는다.
- Review 통과 기준에 맵(걸어 다닐 수 없는 곳에 끼이지 않음, 터치로 어디든 갈 수 있음, 막힌 곳의 까닭이 보임), 미니게임(끝낼 수 없는 판이 없음, 실패해도 이야기가 이어짐), 그림 수준, 움직임의 부드러움(낮은 사양 태블릿)을 더한다.

### 5. 사용자가 읽고 승인할 수 있게

- 맨 위에 **"한눈에 보기"**를 둔다: 한 판이 어떻게 흘러가는지(맵 → 대화 → 놀이 → 맵 …)를 그림 없이 글 열 줄 안팎으로, 봄 한 계절을 예로 들어 쓴다.
- "사용자 결정 필요"(13.2)를 새로 짠다. 적어도 다음을 올린다: 한 판의 길이와 수업에서 쓰는 법, 넣을 재미 요소 목록, 조작 방법, 새 패키지 여부, 첫 조각의 범위. 항목마다 권장안과 까닭 한 줄.
- 길이 한도는 **720행**으로 늘린다. 넘을 것 같으면 뒤 상황(②~⑦)의 예시 장면 표를 상황마다 두세 줄로 줄이고 "그 상황을 만들 때 다시 짠다"고 적는다. ①의 20장면 뼈대는 새 짜임(큰일과 작은 일)에 맞게 다시 쓴다.
- 판 번호는 3판으로 두고, 맨 위 "무엇이 바뀌었나"에 이번 변화(실록 대조, 미연시 구도와 대화, 롤플레잉 맵, 재미 요소, 캔바 그림)를 모두 적는다. 상태는 "사용자 승인 전"으로 고친다.
