# Review 서브에이전트 지침 — 태블릿 바퀴 (홈 화면에 추가)

## 맡은 일

Build 서브에이전트가 만든 **태블릿 바퀴**를 직접 돌려서 검증하고 결과를 `review.md`에 쓴다. 작은 바퀴다. 지금의 `review.md`(1-다)는 `docs/reviews/1-다.md`로 옮기고, `review.md`는 이번 결과로 새로 쓴다.

먼저 읽는다: `agents/build-01d-tablet.md`(Build가 받은 지침), `spec.md`의 3절, 5.4, 10절 끝의 "태블릿과 홈 화면"과 "Vercel 설정", 11절의 태블릿 바퀴 줄·Review 기준("홈 화면", "인터넷과 새 판", "두 엔진")·사용자가 해 볼 점검표, 12.4, 13.1의 24~28번.

이번 범위: 매니페스트, 느티나무 아이콘, `index.html`의 메타, 홈 화면에서 열렸는지 가리기와 기기별 안내, 세로 안내, 판 번호와 "이 기기", 새 판 알아차리기, 그리고 1-다 다시 보기의 권고 30~34·37번. **서비스 워커는 넣지 않는 것이 맞다**(사용자 결정: 인터넷이 있을 때만 연다).

바퀴 1-다는 커밋 `623b8e1`에 있고 운영 주소 `https://joseon-year.vercel.app`에 올라가 있다. 이번 바퀴의 변화는 아직 커밋되지 않았다(운영 주소에는 없다).

## 수정 범위

- 고칠 수 있는 것: `review.md`, `docs/reviews/`, `docs/shots/review-1d/`. 코드를 고치지 않는다.
- 망가뜨려 보는 시험은 새로 만든 복사본에서 한다. 패키지 설치, git 커밋·푸시를 하지 않는다. 5173 서버는 사용자의 것이니 끄지 않는다. 네가 띄운 것은 끝나면 멈춘다. 사파리를 띄우려 하지 않는다.

## 확인할 것

1. `npm run typecheck`, `npm run build`(복사본), `npm test`. `git diff 623b8e1 --stat`으로 바뀐 것이 Build의 수정 범위 안인지, 패키지 일곱 개 그대로인지, 서비스 워커와 `vercel.json`이 없는지, 저장의 꼴이 3 그대로이고 견본이 그대로인지.
2. **매니페스트와 아이콘**: 빌드본을 크롬으로 열어 매니페스트 검사에 오류·경고가 없는지, 설치할 수 있다고 나오는지, 값이 spec 10절과 같은지(`start_url`·`scope`·`id`가 운영 주소 `https://joseon-year.vercel.app/`에서 옳게 풀리는지 따져 본다 — 주소 끝에 `index.html`이 붙거나 `?seed=` 같은 것이 붙었을 때도). 아이콘 넷을 눈으로 본다: 게임의 느티나무인지, 192와 180에서도 알아보이는지, 흐리거나 뭉개지지 않았는지, maskable이 둥글게·네모나게 잘려도 나무가 온전한지. 아이콘 만드는 스크립트를 복사본에서 다시 돌려 같은 파일이 나오는지.
3. **기기별 안내**: 갤럭시탭·아이패드·PC로 꾸며(사용자 에이전트, 손가락 점, 화면 크기) 탭으로 열었을 때와 홈 화면에서 연 것처럼 꾸몄을 때 안내가 뜨고 안 뜨는지. 안내의 글이 spec 5.4와 맞고 5학년이 읽을 만한지, 글자 20px 이상·단추 56px 이상인지, 여섯 크기(1024×768, 1024×690, 1080×810, 1280×800, 1366×650, 1920×1080)에서 넘치지 않는지. "나중에 할게요"로 닫고 다시 볼 수 있는지. 탭에서 "처음부터"를 누를 때의 물음이 지나치게 겁을 주거나 헷갈리지 않는지. 기기를 잘못 가리는 경우(안드로이드 폰, 아이폰, 터치 되는 윈도 노트북, "데스크톱 사이트" 보기의 아이패드)에 무슨 일이 생기는지.
4. **세로 안내**: 태블릿을 세로로 꾸몄을 때만 뜨고 가로로 돌리면 사라지는지, 게임 상태가 망가지지 않는지.
5. **판 번호와 "이 기기"**: 값이 실제와 맞는지, 학생이 실수로 열어도 문제없는지.
6. **새 판 알아차리기**: 빌드를 다시 해 코드 파일 이름을 바꾸고 시간을 흉내 내어 — 30분 넘게 가려졌다 돌아오면 저장하고 다시 불러오는지, 그 뒤 "이어 하기"가 서 있던 자리에서 되는지, 30분이 안 됐거나 새 판이 없거나 인터넷이 끊겼으면 아무 일도 없는지, 대화·놀이 도중에는 미루는지. **되풀이해서 다시 불러오는 일이 없는지**(다시 불러온 판이 또 새 판을 찾는 등), 받은 첫 문서가 엉뚱할 때(오류 쪽, 빈 글) 조용히 넘어가는지.
7. **권고 30~34·37번**을 하나씩: 해 ☀ 풀이 알림(읽을 시간과 주인공을 가리지 않는지), 뒷산 "한 짐만 하고 쉰다"의 기력 +1(막다른 길과 균형에 영향이 없는지 엔진으로), 기력이 낮으면 해가 준다는 알림, 쪽지와 봇짐의 넘김, 작은 것들.
8. **고치다가 망가진 것이 없는지**: 봄을 두 모습으로 끝까지(덤 포함), 저장하고 이어 하기 몇 때, 화면 크기들에서 넘침, 그림 13장, 인터넷 끊김, 맵의 문과 까닭, 초당 장수, 빌드본에 개발용 값이 없는지.
9. **운영 주소에서만 볼 수 있는 것**은 지금 볼 수 없다(이번 변화가 아직 올라가지 않았다). 커밋 뒤에 조정자가 확인할 것을 목록으로 적는다(매니페스트의 `content-type`, 판 번호의 커밋 글자, 아이콘 주소 등).

## Build의 말 (확인된 사실이 아니다)

- 시험 12파일 467개 통과 + 2개 건너뜀. 빌드 JS 303KB. 크롬의 설치 가능 검사에서 막는 까닭 0.
- 192와 180 아이콘은 두 배로 그린 것을 셋으로 나눠 줄였다(정수배가 아니다).
- "이 기기"는 제목 귀퉁이의 판 번호를 누르면 열리는 작은 창이고 그 단추는 44px·18px이다.
- 제목의 "홈 화면에 추가" 단추는 PC에도 보인다. 기기 가리기가 안드로이드 폰과 아이폰도 태블릿으로 친다.
- 설치 물음 단추를 눌렀을 때의 실제 흐름은 눌러 보지 못했다.
- 새 판으로 다시 불러올 때 맵의 알림이나 "미션이 풀림" 종이가 떠 있어도 불러온다.
- 뒷산 "한 짐만 하고 쉰다"에 기력 +1(대본은 조정자가 맞춰 고쳤다).
- 37번의 ㉤(놀이판이 고른 논과 상관없이 한 배미)은 그대로다.
- 실제 태블릿과 WebKit은 이번에도 보지 못했다.

## `review.md` 형식

1. 판정(통과 / 고친 뒤 통과 / 불통과)과 까닭 2. 직접 돌린 것 3. 발견 사항 표(번호, 심각도, 무엇, 어디, 어떻게 확인했나, 고칠 방향) 4. 안내 문구에 대한 평가 5. Build가 밝힌 것에 대한 판단 6. 커밋 뒤 운영 주소에서 확인할 것 7. 사용자가 실제 태블릿에서 확인할 것(spec 11절 점검표에 비추어, 이번 판에서 볼 수 있는 것만) 8. 확인하지 못한 것.
