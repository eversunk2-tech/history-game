# Review 지침 — 대화 넘기기(→ 키와 "아무 곳이나 누르기" 알림)

조정자가 쓴 지침이다. 너는 Build와 따로 본다. Build의 말은 견주기만 하고, 판단은 직접 돌려서 얻는다.

## 무엇을 보나

- 대상: 이 작업 폴더(git worktree, 가지 `talk-keys`)의 커밋하지 않은 바뀜. 바탕은 `main`(3판 최종판)이다. `git diff main`으로 바뀐 것만 본다.
- 기준: 같은 폴더의 `agents/build-talk-keys.md`(사용자의 요청 원문, 할 것 1~5, 고치지 않는 것).

## 볼 것

1. **세 명령**: `npm run typecheck` 오류 0, `npm test` 실패 0(늘어난 시험 수, 지운 시험 0), `npm run build` JS 하나·`import(` 0.
2. **범위**: 바뀐 파일이 지침의 범위 안인가(`Talk.tsx`·자판·누름 처리·돌아보기·알림 글·시험·문서). 대화의 글·차례·선택지, `TapGate`의 틈, 맵·일 놀이·그림·저장이 그대로인가.
3. **사용자의 요청대로 되나**(머리 없는 크롬, 손가락 누름과 자판 둘 다 — 1180×820과 1024×768):
   - 대화 창이 뜬 동안 → · Space · Enter · 화면 아무 곳(배경·인물·대사 창·위쪽 띠의 빈 곳과 글) 누름이 **한 번에 한 창**씩 넘어간다. 마우스 누름과 터치(`Input.dispatchTouchEvent`) 모두.
   - 선택지가 뜬 때: →가 아무것도 고르지 않는다. ↑↓·Enter·Space·선택지 누르기는 앞과 같다. 배경을 눌러도 고르지 않는다.
   - 쪽지(배움 쪽지)와 일 놀이 단계: →·배경 누름이 그 화면을 건너뛰지 않는다. "← 나중에 할게요"·쪽지의 단추는 그대로.
   - →를 길게 누르고 있으면(되풀이 누름) 한 창만 넘어간다. 빠르게 두 번 두드려도 한 창(`TapGate`).
   - 알림 줄: 한 판의 처음 몇 창에만 보이고 그 뒤 사라진다. 글이 문서와 같고, 크기·대비가 기준(18px 넘게, 4.5:1)을 넘는다. 대사 글을 가리지 않는다.
   - 한 해 돌아보기: →가 "다음", ←가 "이전"과 같다. 막힌 때(남길 것을 고르기 전 등)는 아무 일도 없다.
   - 맵에서(대화 장면이 없을 때) →·Space가 앞과 같게 돈다(걷기 등 — 대화의 자판 처리가 맵으로 새지 않는다).
4. **망가뜨려 보기**: 스크래치 복사본에서 →의 처리, `choose`에서 막는 줄, `ev.repeat` 막는 줄, 띠 누름, 알림 수를 하나씩 망가뜨려 새 시험이 잡는지 본다.
5. **새로 생긴 탈**: 대화 장면을 닫는 그 누름이 맵의 걷기로 새지 않는가, 이어 하기로 연 판에서도 알림이 맞게 보이는가.

6. **Build가 밝힌 것(조정자가 더함 — 판단해 줄 것)**
   - `src/state/store.ts`에 `playNo` 신호를 더했다(지침에 없던 파일). 이어 하기에서도 알림을 다시 세려고. 저장 꼴을 건드리지 않았는지, 다른 길(새로 시작·이어 하기·개발 주소)에서 부작용이 없는지 본다.
   - 넘기기 판정을 `src/ui/advance.ts`(새 파일)로 뗐다. 대화 장면 밖의 누름을 문서 전체에서 받는다 — 다른 창(`aria-modal`)·단추·`data-own`을 제외한다고 했다. 대화 장면이 닫힌 뒤에도 문서의 누름 처리가 남아 맵의 누름을 먹지 않는지(듣는 것을 떼는지) 꼭 본다.
   - 알림 글을 "화면 어디를 눌러도 넘어가요(→·Space 키도 돼요)"(30자)로 정했다.
   - 돌아보기의 "남길 것" 장에서는 →가 아무것도 하지 않게 했다("남기고 이야기책으로"는 되돌릴 수 없는 일이라). 이 판단이 맞는지.
   - `docs/spec-3판.md`의 9.2·4절 6번에 넘기기·알림·←→를 적었다.
   - `npm test`가 사용자 저장소의 `node_modules/.vite/vitest/…/results.json`과 `node_modules/.vite-temp/`를 건드렸다(node_modules가 링크라서). 동작에 영향이 없는지 본다.
